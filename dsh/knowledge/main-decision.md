# Evidence-driven main-agent decisions

The main agent may inspect facts, discover eligible tools, record a plan, execute its selected tool, then inspect feedback and revise or stop. Tool eligibility is host-controlled; the model supplies a reason, expected effect and uncertainties. Expected effects are hypotheses, never measurements. No Maker or RSI is enabled.

New native workflows pause at macro placement, placement, routing, post-DRC review and finalization until the main agent records a valid plan from current observations. Dependency order and frozen inputs never change. A complete old task may be opened for read-only production evidence plus separate experiments; none of its accepted stages are rerun.

Quality repair requires observations. A residual DRC count alone cannot identify the cause. Query nets and all terminal pages, tracks, blockages and routed branches. A reviewed local geometry package may supply pin/obstacle/short evidence tied to a parent DEF hash. Its scope cannot be generalized to an entire chip.

Registered experiments reuse hashed baselines, change only a declared factor, and execute in an isolated server workspace. A new candidate is independently checked with the same checker, libraries and rule coverage. Compare rule categories as well as totals. A regression or missing connectivity evidence prevents promotion. Production artifacts are never overwritten by these phase-one experimental tools.

Existing negative experiments should be reused instead of repeated. A reduction in available routing layers is a hypothesis about search space, not a guaranteed repair; it may worsen congestion and shorts. No qualified option, repeated failure, no improvement, uncertain metrics or budget exhaustion are valid reasons to stop and preserve the baseline.
